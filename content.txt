1. Project Objective
The objective is to build a polished Blackjack frontend using React and TypeScript while learning React
through a real project instead of studying isolated examples.
You already have a TypeScript version of the Blackjack game. The React version turns that logic into an
interactive browser application.
By the end, you should understand how a React application starts, how components are created, how
data moves between components, how user actions update state, how reusable components are
designed, and how React connects to existing business logic.
What the finished application should feel like
• A user opens the Blackjack application in a browser.
• The screen shows a Blackjack table with a dealer area and a player area.
• The user selects a betting amount and starts a round.
• The application deals cards.
• The user clicks HIT or STAND.
• The interface updates immediately without a page refresh.
• The dealer plays according to the game rules.
• The application shows WIN, LOSS, PUSH, BLACKJACK, or BUST.
• The balance changes according to the result.
• The user starts another round.
What this project is teaching
The game itself is the subject. React is the learning platform. Each feature gives you a reason to learn
a React concept.
2. React in Simple Terms
React is a JavaScript library for building user interfaces. A React application is built from components. A
component is a reusable piece of the screen with its own structure and behavior.
For this project, think of the application as a collection of small UI pieces rather than one large file.
App
├── Header
└── GameTable
├── Dealer area
│ └── Hand

├── Player area

├── BettingPanel
├── ActionButtons

React renders these components and updates the parts of the screen whose data changes. The user
does not need to refresh the browser after clicking a button.

6. App.tsx: The Application Coordinator
App.tsx is the top-level component. It uses the Blackjack hook and passes the required data and
functions to the UI.
function App() {
const {
playerHand,
dealerHand,
balance,
bet,
status,
startRound,
hit,
stand,
resetGame,
} = useBlackjack();
return (
<div className="app">
<Header balance={balance} />
<GameTable
playerHand={playerHand}
dealerHand={dealerHand}
balance={balance}
bet={bet}
status={status}
onBet={startRound}
onHit={hit}
onStand={stand}
onNewRound={resetGame}
/>
</div>
);
}
App does not contain the visual details of every card. It coordinates the major pieces. This is a key
React design principle: keep large components focused on composition and move detailed behavior
into smaller components.
7. Game Logic Layer
7.1 Card
Card represents one playing card. It stores a numeric value and a suit. It also converts values such as
1, 11, 12, and 13 into A, J, Q, and K for display.
7.2 Deck
Deck creates the 52 cards, shuffles them, resets the deck, and deals cards.
7.3 BlackjackGame
BlackjackGame manages a complete round. It stores the player hand, dealer hand, balance, bet, and
current game status. It contains actions such as startRound, hit, stand, and resetGame.
7.4 types.ts
types.ts defines shared TypeScript types. Suit describes the four suits. GameStatus describes the
possible states of the game. ICard describes the shape of a card.
Why keep this outside React?
Blackjack rules are business logic. They do not need to know how the browser looks. Keeping them
separate makes the code easier to test, reuse, and maintain.
8. Utility Functions
gameUtils.ts contains calculations that are useful in multiple places.
getHandValue(cards)
isBlackjack(cards)
isBust(cards)
getHandValue calculates a hand's score and handles the special behavior of an Ace. An Ace starts as
11 and changes to 1 when needed to prevent a bust.
Learning outcome
Learn to identify logic that is reusable and independent from the UI. This skill is useful in frontend,
backend, and full-stack applications.
9. useBlackjack.ts: The React Bridge
This is one of the most important files for your React learning.
The BlackjackGame class knows the game. React needs state so the screen updates when the game
changes. useBlackjack connects the two.
const [balance, setBalance] = useState(1000);
const [playerHand, setPlayerHand] = useState<ICard[]>([]);
const [dealerHand, setDealerHand] = useState<ICard[]>([]);
const [status, setStatus] = useState<GameStatus>("idle");
What useState means
useState stores information that belongs to the UI. When a state setter runs, React renders the
affected components again.
syncGame
The game class changes its internal values. syncGame copies those values into React state. This gives
React the information needed to update the screen.
Learning outcome
• Understand state.
• Understand re-rendering.
• Understand custom hooks.
• Understand how React can coordinate an existing class-based business layer.
• Learn to separate UI state coordination from UI markup.

11. Card Component
Card receives a card object through props.
interface CardProps {
card: ICard;
hidden?: boolean;
}
Arrays, map, keys, props
useState, events, forms
Event handlers, props
Conditional rendering
Composition, props, conditional UI
The hidden prop lets the dealer's second card appear as a card back during the player's turn.
Concepts
• Props: data sent into a component.
• Optional props: hidden does not have to be supplied.
• Conditional rendering: different markup appears when hidden is true.
• Dynamic classes: the suit determines whether the card receives the red-card or black-card class.
12. Hand Component
A Hand represents a collection of cards. It receives an array and creates one Card component for each
item.
cards.map((card, index) => (
<Card
key={`${card.suit}-${card.value}-${index}`}
card={card}
/>
))
Why map matters
React interfaces often display lists. map transforms data into UI elements. This is one of the most
important patterns you should carry into future projects.
Why key matters
React uses keys to identify list items efficiently between renders. Every rendered list item should have
a stable, meaningful key.

14. ActionButtons Component
This component contains HIT and STAND. It does not own the game logic. It receives functions from its
parent.
interface ActionButtonsProps {
onHit: () => void;
onStand: () => void;
disabled?: boolean;
}
This teaches an important React pattern: a child component triggers behavior owned by a parent
through a function passed as a prop.
15. GameResult Component
GameResult displays the final state of a round. It decides what message to show from the game status.
Examples include YOU WIN, DEALER WINS, PUSH, BLACKJACK, and BUST.
Learning outcome
You learn conditional rendering. The interface should reflect application state. The same component
can display different content without duplicating the entire screen.
16. GameTable Component
GameTable is the main visual area. It places the dealer hand, player hand, betting panel, action
buttons, and result overlay into one game experience.
It also decides which controls are visible. For example, betting appears when status is idle. HIT and
STAND appear while the game is playing.
This is where React starts to feel like a real application
The component is no longer a simple example. It combines state, props, conditional rendering,
reusable components, and user actions.

19. CSS and UI Learning
The CSS layer gives you practical frontend experience alongside React.
• Global CSS establishes page-wide defaults.
• Component CSS keeps styling close to the component.
• Flexbox handles card and control layouts.
• Media queries support smaller screens.
• Transitions create interaction feedback.
• Gradients, shadows, borders, spacing, and typography create the Blackjack table visual.
The visual goal is to build a polished table rather than a plain collection of buttons and text.

25. Corporate Relevance
This project mirrors several patterns used in production frontend applications.
• Reusable components replace duplicated UI.
• Props define communication between components.
• State represents changing application information.
• Business logic stays separate from presentation.
• Types describe contracts between parts of the application.
• Folder structure helps teams locate code quickly.
• CSS is organized around components and global styles.
• User actions flow through explicit event handlers.
The Blackjack domain is small, so you can focus on frontend engineering rather than spending most of
your time understanding a large business domain.

28. Final Project Definition
React Blackjack is a learning-focused interactive web application built with React and TypeScript. The
application uses a separate Blackjack game engine for cards, deck operations, scoring, betting, dealer
behavior, and round results. React provides the browser interface, state coordination, reusable
components, user interaction, and responsive presentation.
The most important result is not the Blackjack game itself. The project gives you a small but complete
environment where you repeatedly practice the same patterns used in larger React applications.
When you later build an e-commerce application, employee dashboard, banking interface, booking
system, portfolio, admin panel, or SaaS frontend, the same ideas will appear again: components,
props, state, events, lists, conditional rendering, forms, hooks, data flow, reusable logic, and
separation between business rules and presentation.
